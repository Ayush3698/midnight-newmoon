## The contract: `PrivateTally`

A minimal yes/no tally. Anyone can cast a vote; the running totals are
public, but no individual vote choice is ever written to the chain.

### Public ledger state vs. private witness

This is the core Midnight concept this contract is built to demonstrate:

**Public ledger state** — `yesCount`, `noCount`, `totalVotes`. These are
Counters declared with `export ledger`, so their values live on-chain and
are visible to anyone reading the contract's state. This is the "public
book" of the application.

**Private witness** — `voteChoice()`. This is declared with `witness`, not
`ledger`. It represents data supplied locally by the caller (their actual
vote) that is *never* written to chain in raw form. Instead, the compiler
turns it into a zero-knowledge circuit: the caller can prove "I correctly
incremented the counter matching my real vote" without the chain, or
anyone watching it, ever seeing the boolean itself.

**`disclose()`** is the deliberate seam between those two worlds. It's
called exactly once in `castVote()`, at the moment a value derived from
private data (`revealedChoice`) needs to influence which public counter
gets bumped. Everything before that call is private computation; everything
after is public. Keeping that boundary to a single, explicit line is the
point — it makes it easy to audit exactly what a contract chooses to leak
about private inputs, and nothing more.

## How to run locally

These steps assume a fresh machine. Anthropic's sandboxed tools can't
reach Midnight's package registries or a live testnet, so this part has
to happen on your own machine.

1. **Install prerequisites**
   - Node.js 22.x
   - Docker (for the local proof server)
   - Docs: https://docs.midnight.network — "Getting Started" / toolchain
     install section has the current installer commands for the Compact
     compiler; command names/flags shift between releases, so use what's
     on that page rather than trusting any command baked into this repo.

2. **Install project dependencies**
   ```bash
   npm install
   ```
   Open `package.json` and swap the `@midnight-ntwrk/*` version numbers
   for whatever `npm view @midnight-ntwrk/compact-runtime versions` shows
   as current — the placeholders in this scaffold are not real versions.

3. **Compile the contract**
   ```bash
   npm run compile
   # equivalent to: compact compile contract/PrivateTally.compact managed
   ```
   This should produce a `managed/PrivateTally/` folder containing the
   compiled circuits and proving/verifying keys. **Screenshot this
   terminal output** (it should list the circuits: `castVote`,
   `getResults`) — that's one of your submission screenshots.

4. **Run the test suite**
   ```bash
   npm test
   ```
   Fill in the `TODO`s in `src/PrivateTally.test.ts` using the real
   generated contract module path shown inside your `managed/` folder,
   then make sure `npm test` is green before you submit.

5. **Start the local proof server** (needed before deploying)
   ```bash
   docker run -p 6300:6300 midnightnetwork/proof-server -- 'midnight-proof-server --network preview'
   ```
   (Adjust the image tag / flags to whatever the current docs specify.)

6. **Deploy to Preview or Preprod**
   Follow the current Midnight deployment guide to point your wallet at
   the Preview or Preprod network, fund it from the faucet, and deploy:
   ```bash
   # example shape — confirm exact CLI/SDK calls in current docs
   npx midnight-deploy contract/PrivateTally.compact --network preview
   ```
   **Screenshot the successful deploy output showing the contract
   address**, and paste the address below.

7. **Record the deployed address**
   ```
   Network: Preview / Preprod
   Contract address: <PASTE_ADDRESS_HERE>
   ```

8. **Commit as you go.** Aim for 5+ meaningful commits (toolchain setup,
   contract written, tests added, compiled output added, deployment +
   README) rather than one giant commit at the end.

## Initial product idea

*(Replace this paragraph with your own idea — this is a placeholder to
show the shape/length expected.)*

**PrivateTally** could grow into a lightweight tool for community
governance on Midnight — small DAOs or local groups running sensitive
votes (e.g., budget allocation, moderation decisions) where members want
verifiable, tamper-proof results without exposing how any individual
voted. Beyond Level 1's simple yes/no tally, later levels could add
per-proposal vote windows, weighted voting via private token balances,
and a public dashboard that only ever surfaces aggregate results —
extending the same public-ledger/private-witness split into a real
front-end.
